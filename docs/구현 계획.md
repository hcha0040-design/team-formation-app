## 3. DB 설계(`schema.sql`)

5장 최소 참고안에 제약을 더한다.

```sql
tf_students(id serial pk, student_no text unique not null, name text not null,
            main_role text check (main_role in (6개 역할)), password_hash text not null,
            is_admin boolean default false)
tf_student_sub_roles(student_id int references tf_students on delete cascade,
                     role text check (role in (6개 역할)), primary key (student_id, role))
tf_teams(id int pk, name text unique not null)              -- id = 팀 번호(1, 2, …)
tf_members(team_id int references tf_teams, slot_no int check (slot_no between 1 and 4),
           student_id int unique references tf_students, primary key (team_id, slot_no))
tf_applications(id serial pk, team_id, student_id, status text check (status in ('대기','승인','거절')),
                reason text, created_at timestamptz default now(), decided_at timestamptz)
  + unique index on (student_id) where status = '대기'      -- 한 학생은 대기 지원 1개
tf_votes(application_id references tf_applications on delete cascade, voter_id,
         vote text check (vote in ('찬성','거부')), primary key (application_id, voter_id))
tf_settings(key text pk, value text)                        -- closed = 'true'/'false'
tf_ai_logs(id serial pk, created_at, attempt int, model text, outcome text, detail text, elapsed_sec real)
```

- 명단 올리기: 한 트랜잭션 안에서 관리자를 뺀 모든 행을 지우고 다시 넣는다.
- 학생 비밀번호는 모두 `1234`이므로 bcrypt 해시를 한 번만 만들어 모든 학생에게 쓴다(16명 × 0.3초를 피함).
- 앱이 시작될 때 테이블이 없으면 `schema.sql`을 실행하고, 관리자 계정을 upsert한다.

## 4. 동시성과 트랜잭션

- **지원**: 팀 행을 `SELECT … FOR UPDATE`로 잠근 뒤 PRD 5.2절의 검사를 한다.
  - 빈 팀이면 `tf_members`에 바로 넣고 지원을 '승인'으로 기록한다.
  - 넣을 때 유일성 위반(`UniqueViolation`)이 나면 막힘으로 돌린다.
- **투표**: `tf_votes`에 넣는다(기본 키가 중복 투표를 막음).
  - 같은 트랜잭션에서 팀 행을 잠그고 결과를 정한다.
  - 거부가 하나라도 있으면 거절한다.
  - 지금 팀원 모두가 찬성했으면 6.2절 재검사를 해서 승인하거나 거절한다.
  - 승인하면 비어 있는 가장 작은 `slot_no`로 넣는다.
- **마감**: 대기 지원을 거절하고(이유: 모집 마감), 1명뿐인 팀의 팀원 행을 지운다. `closed`를 켠다.
- **확정**: 배정안을 다시 검사한 뒤 `tf_members`에 넣는다. 실패하면 전체를 되돌린다.
- **연결이 끊긴 경우**: `OperationalError`/`InterfaceError`가 나면 캐시를 비우고 한 번 다시 연결한다.

## 5. 규칙 함수(`tf/rules.py`)

모두 DB 없이 학생 정보 목록만 받는 순수 함수로 만들어 단위 시험한다.

- `can_cover(student, role)`: 학생이 그 역할을 맡을 수 있는지(주 역할이나 보조 역할)
- `required_filled(members)`: {기획자, 웹 프로그래머}를 서로 다른 학생에게 짝지을 수 있는 최대 수. 역할이 2개뿐이라 경우를 직접 따져도 됨
- `check_join(members, newcomer)`: 정원, 주 역할 중복, 필수 역할 자리를 검사해 막힘 이유를 돌려줌(없으면 `None`). 지원과 승인 직전 재검사에 함께 씀
- `validate_assignment(teams, unassigned, plan)`: 다섯 가지 검사. 어긴 항목의 목록을 돌려줌
- `search_assignment(teams, unassigned)`: 백트래킹 완전 탐색. 가지치기 조건은 아래와 같음
  - 정원 초과
  - 주 역할 중복
  - 남은 학생 수 < 아직 2명이 안 된 팀이 더 받아야 할 수
- `explain_infeasible(teams, unassigned)`: 배정이 없을 때 사람이 읽을 이유. 예: "팀3에 웹 프로그래머를 맡을 학생이 없음"

## 6. AI 배정(`tf/ai.py`)

1. `MODELS = [1차, 2차, 3차]`: 10/30에 후보 7개를 실제로 불러 보고 정했다([AI 모델 시험 기록](AI%20모델%20시험%20기록.md)).
   - 1차 `nvidia/nemotron-3-ultra-550b-a55b:free` (성공, 47초)
   - 2차 `nvidia/nemotron-3.5-super-vl:free`
   - 3차 `google/gemma-4-31b-it:free`
   - `openrouter/free` 라우터는 쓰지 않는다.
2. 요청 본문은 다음과 같이 보낸다.
   - 팀 구성(팀 번호, 팀원의 주 역할과 보조 역할), 팀이 없는 학생 목록, 팀 규칙
   - "JSON만 답하라: `{"assignments":[{"student_no":"…","team":1}, …]}`"
   - `reasoning: {"effort": "low"}`, `max_tokens` 넉넉히(예: 4000)
3. **전체 120초 제한**: 각 호출을 `ThreadPoolExecutor`에 넣고 `future.result(timeout=남은 시간)`으로 기다린다.
   - 시간이 넘으면 그 호출은 버리고 다음 모델로 넘어간다.
   - `urllib`의 `timeout`도 120초로 함께 준다.
   - 같은 모델을 다시 부르지 않는다(무료 한도: 하루 50회).
4. 응답에서 JSON 부분만 꺼낸다(코드 블록 ``` 안이나 첫 `{`부터 마지막 `}`까지). 학번을 문자열로 맞춘 뒤 `validate_assignment`로 검사한다.
5. 배정은 백그라운드 스레드에서 하고, `assign_status`는 1초마다 다시 그리는 프래그먼트가 진행 상황을 보여 준다. 예: "1차 모델(nemotron-3-ultra) 응답을 기다리는 중… 23초 / 120초".
   - 초 단위 진행은 결과를 0.5초마다 기다리는 반복문에서 갱신한다.
   - 결과는 `tf_ai_logs`에 남긴다. README 5항의 근거로 쓴다.
6. 3차까지 실패하면 `search_assignment`의 결과를 쓰고 "AI 모델 3개가 모두 실패해 앱이 직접 배정함"을 보여 준다.
7. 배정안은 `st.session_state`에 두고, 확정 단추를 누르면 DB에 저장한다.

## 7. 화면 구성

- **로그인 전**: 학번, 비밀번호, 로그인 단추(`login_*` key).
- **공통**
  - 위쪽에 `whoami`(이름, 학번)와 로그아웃 단추를 둔다.
  - `result` 컨테이너에는 `st.session_state["result"]`의 마지막 안내를 그린다.
- **학생**: `@st.fragment(run_every="3s")` 안에 팀 목록과 대기 지원 목록을 모두 넣는다.
  - 팀마다 `team_{n}` 컨테이너 안에 팀원(이름, 주 역할, 보조 역할)과 `apply_{n}` 단추를 둔다.
  - `result`도 프래그먼트 안에 둔다. 프래그먼트 안 단추를 누르면 프래그먼트만 다시 실행되기 때문이다.
  - 내 팀의 대기 지원마다 `vote_yes_{학번}`, `vote_no_{학번}` 단추를 둔다. 이미 투표했으면 "내 투표: 찬성"을 보여 준다.
- **관리자**
  - 명단 올리기(`admin_roster_file`, `admin_team_count`, `admin_start`)
  - 모집 마감(`admin_close`)
  - 팀 목록과 `unassigned`
  - AI 배정(`admin_assign`, `assign_status`), 배정안 표, 확정(`admin_confirm`)
  - 팀 목록과 `unassigned`는 프래그먼트로 자동 갱신하고, AI 배정 영역은 프래그먼트 밖에 둔다. 긴 호출 중에 자동 갱신과 겹치지 않게 하기 위함이다.
- 주의: 같은 key를 한 화면에 두 번 그리면 오류가 난다. 팀 목록은 화면당 한 번만 그린다.

## 8. DB 일시정지 막기

- `.github/workflows/keepalive.yml`: `schedule: cron "0 0 * * *"`(매일 09:00 한국 시각)과 `workflow_dispatch`를 둔다.
- 하는 일: `pip install psycopg2-binary` 후 `select count(*) from tf_students`를 실행한다.
- `DATABASE_URL`은 GitHub 저장소 Settings > Secrets and variables > Actions에 넣는다. 코드에는 넣지 않는다.
- 비공개 저장소에서도 동작한다(무료 Actions 분 안). 직접 한 번 실행해 초록색인지 확인하고, 그 화면을 README에 남긴다.
